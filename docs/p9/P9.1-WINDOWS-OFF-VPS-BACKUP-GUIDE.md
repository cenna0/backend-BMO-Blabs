# P9.1 Windows Off-VPS Backup Guide

**Decision status:** `LOCKED_FOR_FIRST_CANARY — WINDOWS / POWERSHELL /
TAILSCALE / SCP`

This is the canonical first-canary procedure for pulling an encrypted P9.1
backup from the VPS to the operator-owned Windows PC. It is a future operator
procedure. It has not been executed, no production secret exists, and no real
backup has been transferred or decrypted.

**Current rehearsal state:** `SSH V3 VERIFIED / ENCRYPTED BACKUP ARTIFACT NOT
YET CREATED / WINDOWS TRANSFER NOT YET EXECUTED`

The procedure transfers only three finalized files:

1. `<backup-name>.dump.gpg` — encrypted PostgreSQL custom-format artifact;
2. `<backup-name>.dump.gpg.sha256` — SHA-256 checksum of the encrypted file;
3. `<backup-name>.manifest.json` — sanitized manifest.

The exact production basename must be supplied by the implemented backup tool.
The expected artifact pattern is currently `p9-daily-<UTC>` or
`p9-weekly-<UTC>`, but the operator must verify the actual remote listing and
manifest before every pull.

Never transfer a plaintext `.dump`, PostgreSQL data directory, database
credential, JWT signing key, pairing HMAC key, PostgreSQL password, GPG
passphrase, raw environment file, Docker secret, invitation secret, access
token, or refresh token. Do not use browser download links, unauthenticated
HTTP, public SMB, FTP, wildcards, recursive SCP, or a public VPS address when
the verified Tailscale path is available.

## 1. Windows prerequisites

### Windows and PowerShell

Built-in Windows PowerShell is sufficient; PowerShell 7 is not required. The
operator records only version and capacity metadata:

```powershell
$ErrorActionPreference = 'Stop'
$PSVersionTable.PSVersion
Get-ComputerInfo -Property WindowsProductName,WindowsVersion,OsBuildNumber
Get-Date -Format o
[DateTime]::UtcNow.ToString('o')

$backupRoot = 'D:\codex\BMO-backups'
$incomingRoot = 'D:\codex\BMO-backups\incoming'
$drive = (Split-Path -Qualifier $backupRoot).TrimEnd('\')
Get-CimInstance Win32_LogicalDisk -Filter "DeviceID='$drive'" |
    Select-Object DeviceID,FileSystem,FreeSpace,Size
```

For this rehearsal, use the fixed `D:\codex\BMO-backups` root and its
`incoming` subdirectory. Do not silently substitute a Windows username,
OneDrive folder, or cloud-sync folder. A different local or external-drive
root requires a separately recorded operator decision and is not active here.

### Tailscale

Install Tailscale only from the [official Windows installation
documentation](https://tailscale.com/docs/install/windows). Sign in to the
operator-controlled tailnet and confirm both the Windows PC and VPS are
visible. The VPS Tailscale machine name or current Tailscale IP is not a
permanent constant and must be checked before each transfer.

The preferred read-only preflight is:

```powershell
Get-Command tailscale.exe -ErrorAction SilentlyContinue
tailscale.exe version
tailscale.exe status
tailscale.exe ping <TAILSCALE_HOST>
Test-NetConnection <TAILSCALE_HOST> -Port 22
```

`<TAILSCALE_HOST>` must be replaced only after the operator verifies the
machine identity in the tailnet. A successful Tailscale ping and TCP/22 test
prove private reachability, not SSH authorization. Do not expose PostgreSQL,
the backup directory, or a new public listener to make the test pass.

If Tailscale is disconnected or the machine identity is unclear, stop. Do not
fall back to a public VPS IP.

### Windows OpenSSH client

The canonical transfer tool is the Windows OpenSSH client `scp.exe`. Microsoft
documents `ssh.exe`, `scp.exe`, and the OpenSSH feature on the [OpenSSH for
Windows overview](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-overview).

```powershell
Get-Command ssh.exe -ErrorAction SilentlyContinue
Get-Command scp.exe -ErrorAction SilentlyContinue
ssh.exe -V
scp.exe -V
```

If the commands are absent, use Windows Settings → System → Optional features
→ View features → OpenSSH Client, or the official Windows OpenSSH capability
path. Installation is a separate operator action and is not executed by this
guide. Do not introduce PuTTY, WinSCP, or another transfer tool while OpenSSH
is available.

### GnuPG and Gpg4win

Install Gpg4win only from the [official Gpg4win
site](https://www.gpg4win.org/). The command-line component is GnuPG; Kleopatra
and GpgEX are optional interfaces. Confirm the executable without exposing
key material:

```powershell
Get-Command gpg.exe -ErrorAction SilentlyContinue
gpg.exe --version
```

The first-canary artifact uses symmetric GPG AES-256. The passphrase is entered
interactively by GnuPG’s pinentry flow. Never put it in a PowerShell script,
command argument, transcript, clipboard-history note, documentation, or log.
The optional Kleopatra flow must follow the same rule.

## 2. Windows backup directory

The operator-approved Windows root is:

```text
D:\codex\BMO-backups\
├── incoming\
├── verified\
├── milestones\
├── restore-tests\
└── logs\
```

- `incoming` contains newly transferred files that are not trusted yet.
- `verified` contains only complete sets that passed checksum and manifest
  checks.
- `milestones` contains manually protected milestone sets outside weekly
  rotation.
- `restore-tests` contains temporary plaintext output only during an approved
  restore rehearsal.
- `logs` contains sanitized verification records only.

The active first-canary incoming destination is
`D:\codex\BMO-backups\incoming`. `%USERPROFILE%\Documents\BMO-Backups` is
not the active operator path for this rehearsal, and no alternate path is
implicitly authorized.

The GPG artifact remains encrypted in `incoming`, `verified`, and
`milestones`. Recovery passphrase/material must not be stored unencrypted in
these directories or beside an artifact. The additional offline copy must be
physically or logically separate. Do not enable OneDrive or another sync
client by assumption.

Create the directories only during the future operator procedure:

```powershell
# FUTURE OPERATOR ACTION — DO NOT RUN DURING READINESS
$ErrorActionPreference = 'Stop'
$backupRoot = 'D:\codex\BMO-backups'
'incoming','verified','milestones','restore-tests','logs' | ForEach-Object {
    New-Item -ItemType Directory -Path (Join-Path $backupRoot $_) -Force | Out-Null
}
Get-ChildItem -LiteralPath $backupRoot -Directory | Select-Object Name,FullName
```

Do not implement automatic deletion during the first canary. Manually retain
four latest verified weekly sets and at least these protected milestones:

- `pre-p9.1-production`;
- `post-p9.1-migration`;
- `post-p9.1-production-verified`.

Each milestone set contains the encrypted artifact, checksum, manifest, and a
sanitized verification record—never plaintext.

## 3. SSH authentication and host-key safety

Use a dedicated operator SSH key in the Windows OpenSSH user profile, for
example under:

```text
%USERPROFILE%\.ssh\<approved-backup-pull-key>
```

The exact filename is operator-controlled. If an approved key already exists,
verify it instead of replacing it. Do not generate or install the real key in
this task. Do not copy the GitHub repository deploy key to Windows, and never
reuse a JWT key, pairing HMAC key, database password, or backup encryption key
for SSH.

Check metadata without printing the private key:

```powershell
$sshKey = Join-Path $env:USERPROFILE '.ssh\<approved-backup-pull-key>'
Get-Item -LiteralPath $sshKey | Select-Object FullName,Length,LastWriteTime
Get-Acl -LiteralPath $sshKey | Select-Object Owner,AccessToString
ssh.exe -G bmo-admin@<TAILSCALE_HOST> | Select-String 'userknownhostsfile|identityfile'
```

The Windows ACL must restrict the private key to the operator and approved
system administrators. The operator records a host-key fingerprint through an
approved out-of-band channel and uses the normal OpenSSH known-hosts file.
Use `StrictHostKeyChecking=ask`; do not automatically accept an unexplained
host-key change. If the key changes, stop and verify the VPS identity with the
operator before continuing.

Lost or stolen Windows PC: revoke the SSH public key on the VPS, revoke the
PC’s Tailscale access, rotate any secret that may have been readable, and
follow the incident runbook. Do not copy a replacement private key into this
documentation or evidence.

## 4. Canonical PowerShell pull

This is a placeholder procedure. Replace every angle-bracket placeholder only
after checking the current Tailscale identity, exact remote directory, exact
basename, approved SSH account, and local destination. Do not run this
procedure during readiness.

### Step 1 — prepare a timestamped incoming directory

```powershell
# FUTURE OPERATOR ACTION — DO NOT RUN DURING READINESS
$ErrorActionPreference = 'Stop'
$backupRoot = 'D:\codex\BMO-backups'
'incoming','verified','milestones','restore-tests','logs' | ForEach-Object {
    New-Item -ItemType Directory -Path (Join-Path $backupRoot $_) -Force | Out-Null
}
$transferId = Get-Date -Format 'yyyyMMdd-HHmmss'
$incoming = Join-Path $backupRoot ("incoming\$transferId")
New-Item -ItemType Directory -Path $incoming -Force | Out-Null
```

### Step 2 — verify the private source and exact remote set

Use the verified Tailscale name or current verified Tailscale IP, not a public
VPS address. Inspect only the three exact paths:

```powershell
$RemoteUser = 'bmo-admin'
$TailscaleHost = '<TAILSCALE_HOST>'
$RemoteDir = '<REMOTE_EXACT_PATH>'
$BackupName = '<BACKUP_NAME>'
$SshKey = Join-Path $env:USERPROFILE '.ssh\<approved-backup-pull-key>'
$KnownHosts = Join-Path $env:USERPROFILE '.ssh\known_hosts'

$remoteFiles = @(
    "$RemoteDir/$BackupName.dump.gpg",
    "$RemoteDir/$BackupName.dump.gpg.sha256",
    "$RemoteDir/$BackupName.manifest.json"
)

foreach ($remoteFile in $remoteFiles) {
    & ssh.exe -i $SshKey `
        -o IdentitiesOnly=yes `
        -o StrictHostKeyChecking=ask `
        -o UserKnownHostsFile=$KnownHosts `
        "${RemoteUser}@${TailscaleHost}" `
        "stat --format='%n %s' -- '$remoteFile'"
    if ($LASTEXITCODE -ne 0) { throw 'remote exact-file inspection failed' }
}
```

The remote command must report exactly one existing nonzero file for each
expected path. Do not use a wildcard or recursive listing. The manifest is
sanitized by the backup tooling, but it is still treated as untrusted input
until verified locally.

### Step 3 — pull exactly three files with `scp.exe`

```powershell
& scp.exe -i $SshKey `
    -o IdentitiesOnly=yes `
    -o StrictHostKeyChecking=ask `
    -o UserKnownHostsFile=$KnownHosts `
    "${RemoteUser}@${TailscaleHost}:${RemoteDir}/${BackupName}.dump.gpg" `
    "${RemoteUser}@${TailscaleHost}:${RemoteDir}/${BackupName}.dump.gpg.sha256" `
    "${RemoteUser}@${TailscaleHost}:${RemoteDir}/${BackupName}.manifest.json" `
    "$incoming\"
if ($LASTEXITCODE -ne 0) { throw 'SCP transfer failed; do not promote incoming files' }
```

No password or private-key content appears in the command. SSH authentication
must use the approved Windows OpenSSH key or its configured agent. Do not use a
public download link, password prompt copied into a script, wildcard, or
recursive transfer. An unexplained host-key change stops the procedure.

### Step 4 — require all three local files

```powershell
$artifact = Join-Path $incoming "$BackupName.dump.gpg"
$checksumFile = "$artifact.sha256"
$manifestFile = Join-Path $incoming "$BackupName.manifest.json"

foreach ($path in @($artifact,$checksumFile,$manifestFile)) {
    if (-not (Test-Path -LiteralPath $path -PathType Leaf)) {
        throw "required transfer file is missing: $path"
    }
    if ((Get-Item -LiteralPath $path).Length -le 0) {
        throw "required transfer file is empty: $path"
    }
}
```

Any missing, zero-byte, or unexpected transfer is incomplete and remains in
`incoming` for quarantine/review. It is not moved to `verified`.

### Step 5 — parse and verify the checksum

The checksum file must contain exactly one nonempty line with one 64-hex-digit
hash and the exact encrypted filename. PowerShell’s `Get-FileHash` is always
called with `-Algorithm SHA256`:

```powershell
$lines = @(Get-Content -LiteralPath $checksumFile |
    ForEach-Object { $_.Trim() } |
    Where-Object { $_ -ne '' })
if ($lines.Count -ne 1) { throw 'checksum file must contain exactly one line' }

if ($lines[0] -notmatch '^(?<Expected>[0-9A-Fa-f]{64})\s+\*?(?<Name>[^\s]+)$') {
    throw 'checksum file format is invalid'
}
if ($Matches.Name -cne (Split-Path -Leaf $artifact)) {
    throw 'checksum filename does not match encrypted artifact'
}

$expectedHash = $Matches.Expected.ToUpperInvariant()
$actualHash = (Get-FileHash -LiteralPath $artifact -Algorithm SHA256).Hash.ToUpperInvariant()
if ($actualHash -cne $expectedHash) { throw 'encrypted artifact checksum mismatch' }
```

The result is fail-closed for malformed lines, multiple hashes, filename
mismatch, differing hash, zero-byte artifact, and partial transfer.

### Step 6 — validate the sanitized manifest

The manifest must be JSON and must contain exactly the supported sanitized
contract fields:

```text
schemaVersion
backupIdentifier
timestamp
databaseIdentifier
postgresMajorVersion
backupFormat
migrationState
encryptedArtifactFilename
encryptedArtifactSize
sha256
creationResult
```

The current supported schema version is `1`, and the current backup format is
`postgresql-custom-encrypted` (PostgreSQL `pg_dump --format=custom` encrypted
with GPG AES-256). `backupIdentifier` must equal the selected `$BackupName`
exactly, including case. The encrypted filename must equal
`$BackupName.dump.gpg`; its size and SHA-256 must match the local artifact;
`creationResult` must be `success`; PostgreSQL major must be an integer from 1
through 99; and `migrationState` must be a non-empty sanitized status. Any
failure stops promotion.

The following PowerShell shape validates the exact contract without printing
the manifest. Secret-field inspection is recursive so a prohibited property
cannot be hidden inside an object or array:

```powershell
# FUTURE OPERATOR ACTION — DO NOT RUN DURING READINESS
$manifest = Get-Content -LiteralPath $manifestFile -Raw | ConvertFrom-Json
$supportedSchemaVersion = 1
$expectedBackupFormat = 'postgresql-custom-encrypted'
$required = @(
    'schemaVersion','backupIdentifier','timestamp','databaseIdentifier',
    'postgresMajorVersion','backupFormat','migrationState',
    'encryptedArtifactFilename','encryptedArtifactSize','sha256','creationResult'
)

function Assert-NoSecretManifestFields {
    param(
        [Parameter(Mandatory = $true)] [object] $Value,
        [string] $Path = 'manifest'
    )
    if ($null -eq $Value) { return }
    if ($Value -is [System.Management.Automation.PSCustomObject]) {
        foreach ($property in $Value.PSObject.Properties) {
            if ($property.Name -match '(?i)password|passphrase|token|secret|private.?key|credential|connection.?string|dsn|jwt|hmac|invitation|access.?key|refresh.?token|environment|env') {
                throw "manifest contains a prohibited secret-bearing field: $Path.$($property.Name)"
            }
            Assert-NoSecretManifestFields -Value $property.Value -Path "$Path.$($property.Name)"
        }
        return
    }
    if ($Value -is [System.Collections.IEnumerable] -and $Value -isnot [string]) {
        $index = 0
        foreach ($entry in $Value) {
            Assert-NoSecretManifestFields -Value $entry -Path "$Path[$index]"
            $index++
        }
        return
    }
    if ($Value -is [string] -and $Value -match '(?i)postgres(?:ql)?://|-----BEGIN[^\r\n]*PRIVATE KEY-----|--passphrase(?:\s|=)') {
        throw "manifest contains a prohibited secret-bearing value at $Path"
    }
}

Assert-NoSecretManifestFields -Value $manifest
$unexpected = @($manifest.PSObject.Properties.Name | Where-Object { $_ -notin $required })
if ($unexpected.Count -ne 0) { throw 'manifest contains an unsupported or secret-bearing field' }
foreach ($name in $required) {
    $property = $manifest.PSObject.Properties[$name]
    if ($null -eq $property -or [string]::IsNullOrWhiteSpace([string]$property.Value)) {
        throw "manifest field missing or empty: $name"
    }
}

if ([string]$manifest.schemaVersion -notmatch '^\d+$' -or [int64]$manifest.schemaVersion -ne $supportedSchemaVersion) {
    throw 'unsupported manifest schema version'
}
if ([string]$manifest.backupIdentifier -cne $BackupName) { throw 'manifest backup identifier mismatch' }
try { [DateTimeOffset]::Parse([string]$manifest.timestamp) | Out-Null } catch { throw 'manifest timestamp is invalid' }
if ([string]$manifest.databaseIdentifier -notmatch '^[a-z_][a-z0-9_]{0,62}$') {
    throw 'manifest database identifier is invalid'
}
$postgresMajor = if ([string]$manifest.postgresMajorVersion -match '^\d+$') {
    [int64]$manifest.postgresMajorVersion
} else { 0 }
if ($postgresMajor -lt 1 -or $postgresMajor -gt 99) {
    throw 'manifest PostgreSQL major version is invalid'
}
if ([string]$manifest.backupFormat -cne $expectedBackupFormat) { throw 'manifest backup format is invalid' }
if ([string]$manifest.encryptedArtifactFilename -cne "$BackupName.dump.gpg") {
    throw 'manifest artifact name mismatch'
}
$manifestSize = if ([string]$manifest.encryptedArtifactSize -match '^\d+$') {
    [int64]$manifest.encryptedArtifactSize
} else { -1 }
if ($manifestSize -ne (Get-Item -LiteralPath $artifact).Length) {
    throw 'manifest artifact size mismatch'
}
if ([string]$manifest.sha256 -ine $expectedHash -or [string]$manifest.sha256 -ine $actualHash) {
    throw 'manifest checksum mismatch'
}
if ([string]$manifest.creationResult -ine 'success') { throw 'manifest creation result is not success' }
```

The selected `$BackupName`, manifest `backupIdentifier`, checksum filename,
artifact filename, and artifact basename must all agree. Do not log the full
manifest. The sanitized verification record selects only identifier,
timestamp, database identifier, PostgreSQL major, format, migration state,
filename, size, checksum, schema version, and success result.

### Step 7 — verify GPG readability

Enter the passphrase interactively through GnuPG. Never supply it as an
argument, file parameter, PowerShell variable, script value, or clipboard
entry. First attempt a no-retained-output check using the Windows `NUL`
device:

```powershell
& gpg.exe --decrypt --output NUL -- $artifact
if ($LASTEXITCODE -ne 0) { throw 'GPG authentication/readability check failed' }
```

If the installed GnuPG build does not support a reliable `NUL` output check,
perform this only as part of an approved restore rehearsal with a unique
temporary output under `restore-tests`:

```powershell
$restoreTests = Join-Path $backupRoot 'restore-tests'
$temporaryDump = Join-Path $restoreTests ("$BackupName-$transferId.dump")
if (Test-Path -LiteralPath $temporaryDump) { throw 'temporary restore path already exists' }
& gpg.exe --decrypt --output $temporaryDump -- $artifact
if ($LASTEXITCODE -ne 0) { throw 'GPG decryption failed' }
# Use this file immediately for the isolated pg_restore rehearsal.
# Do not sync, back up, or move it to verified/milestones.
```

After the rehearsal, close any process using the file and remove only the
explicitly named temporary file through the approved Windows procedure. This
prevents ordinary access but is not a guarantee of forensic erasure on every
storage device. The encrypted artifact remains the retained backup; plaintext
is never retained or transferred.

### Step 8 — promote the verified set

Promotion occurs only after checksum, manifest, and GPG checks pass. Windows
does not atomically rename three files as one set, so stage them in a temporary
directory and rename that directory on the same volume:

```powershell
$verifiedRoot = Join-Path $backupRoot 'verified'
$verifiedTemp = Join-Path $verifiedRoot ".${BackupName}.verified.tmp-$transferId"
$verifiedFinal = Join-Path $verifiedRoot $BackupName
if (Test-Path -LiteralPath $verifiedFinal) { throw 'verified backup already exists' }
New-Item -ItemType Directory -Path $verifiedTemp -Force | Out-Null
Move-Item -LiteralPath $artifact -Destination $verifiedTemp
Move-Item -LiteralPath $checksumFile -Destination $verifiedTemp
Move-Item -LiteralPath $manifestFile -Destination $verifiedTemp
Rename-Item -LiteralPath $verifiedTemp -NewName $BackupName
```

If promotion is interrupted, leave the named temporary directory for manual
inspection. Do not treat it as verified and do not perform broad deletion.

### Step 9 — write sanitized verification evidence

Write a local log under `logs` containing only:

- backup identifier;
- transfer timestamp;
- source Tailscale machine identity;
- three filenames and sizes;
- expected and actual SHA-256 of the encrypted artifact;
- manifest verification result;
- GPG verification result;
- operator result.

Never write the passphrase, decrypted data, database credentials, private key,
access token, refresh token, pairing code, or raw sensitive database content.

## 5. Transfer schedule and checklists

Perform the manual pull:

- at least once every week;
- before a production database migration;
- after a successful production migration;
- before a high-risk deployment;
- after P9.1 production verification;
- after a material PostgreSQL upgrade;
- after a backup-key or backup-tool change.

### Weekly pull checklist

- [ ] Confirm the Windows PC date/time and destination disk headroom.
- [ ] Confirm Tailscale identity and private TCP/22 reachability.
- [ ] Confirm OpenSSH key path/ACL and known-host entry.
- [ ] Inspect exactly three remote files; do not use a wildcard.
- [ ] Pull only artifact, checksum, and manifest into a new `incoming` folder.
- [ ] Verify existence, nonzero sizes, checksum, and manifest.
- [ ] Verify GPG readability interactively.
- [ ] Promote the complete set to `verified`.
- [ ] Write sanitized evidence.

### Migration and high-risk deployment checklist

Run the weekly checklist before the change. After a successful migration or
deployment, repeat it and record the migration state in the manifest/evidence.
If the pull or verification fails, stop the migration/deployment gate and keep
the last valid local and PC copies.

### Milestone and retention checklist

- [ ] Protect `pre-p9.1-production` before first production migration.
- [ ] Protect `post-p9.1-migration` after migration verification.
- [ ] Protect `post-p9.1-production-verified` after final verification.
- [ ] Retain four latest verified weekly sets.
- [ ] Keep milestones outside ordinary weekly rotation.
- [ ] Do not automatically delete files during the first canary.

### Additional offline-copy checklist

Before final P9.1 production verification, keep one additional encrypted copy
on a separate operator-controlled offline medium. Acceptable categories include
an encrypted removable drive or a separate encrypted offline archive. Do not
select a commercial provider or password manager in this procedure. The
recovery material is encrypted and stored separately from the artifact.

## 6. First Windows restore-rehearsal gate

The first real rehearsal must prove all of the following:

1. Isolated P9.1 tooling creates an encrypted backup, checksum, and manifest.
2. The exact set transfers to Windows over Tailscale and `scp.exe`.
3. PowerShell verifies SHA-256 and manifest fields.
4. GnuPG verifies readability interactively.
5. The exact verified PC copy is used for an isolated fresh-target restore.
6. Migration state, schema, row counts, ownership, settings, audit events,
   login, and `/api/v1/me` pass.
7. Temporary plaintext restore output is removed after use.
8. Sanitized evidence contains no secret or database content.

The rehearsal may use isolated candidate data and does not require production
PostgreSQL. It is not passed until an actual Windows transfer, checksum,
interactive GPG check, and exact-copy restore occur.

## 7. Troubleshooting and stop conditions

- **`ssh.exe`/`scp.exe` missing:** use the official OpenSSH Client optional
  feature path; do not switch tools automatically.
- **Tailscale disconnected:** stop; restore tailnet access and reverify the VPS
  identity and port 22.
- **Hostname/IP unreachable:** re-check current Tailscale status; never use a
  public VPS address as an unreviewed fallback.
- **SSH host-key mismatch:** stop and verify out of band; never accept a new
  key blindly.
- **Permission denied:** inspect SSH account/key ACL/remote file permissions;
  do not copy credentials or broaden access.
- **Remote path unreadable:** stop and obtain the exact path from the approved
  operator procedure; do not use recursive or wildcard SCP.
- **Partial transfer:** leave it in `incoming`, do not promote, and retry only
  after the source set is confirmed unchanged.
- **Checksum mismatch:** quarantine the incoming set; retain the last verified
  copy; do not restore or delete broadly.
- **Malformed checksum or manifest mismatch:** stop promotion and request a
  corrected finalized artifact set.
- **Insufficient disk:** stop before transfer or decryption; do not delete
  milestones or verified backups automatically.
- **`gpg.exe` missing:** install Gpg4win from the official source in a separate
  approved maintenance action.
- **Wrong passphrase or corrupt artifact:** stop; never retry by recording the
  passphrase; verify the recovery inventory and source checksum.
- **Temporary plaintext cleanup failure:** stop restore operations, isolate the
  file, preserve sanitized evidence, and follow the secret incident runbook.
- **Lost/stolen PC or SSH key:** revoke Tailscale/SSH access, rotate affected
  credentials, and do not claim the PC copy is trusted.
- **Duplicate basename:** stop and require an exact new transfer directory;
  never overwrite a verified set.

Every failure prevents promotion from `incoming` to `verified` and prevents
the off-VPS restore gate from being marked passed.

## 8. Expected safe output patterns

These are illustrative shapes only. They contain no real host, username,
fingerprint, checksum, or secret:

```text
WindowsProductName: <Windows version>
DeviceID FileSystem FreeSpace Size: <drive metadata>
<verified-tailnet-machine> <verified-tailnet-address> <online-state>
<remote-exact-path>/<backup-name>.dump.gpg <positive-byte-count>
Algorithm: SHA256
Hash: <64-HEX-DIGEST>
Path: <local-verified-artifact>
verification: success
```

Safe output contains metadata, paths, sizes, status, and a sanitized result.
It never contains a passphrase, private key, token, database row, decrypted
content, or raw environment value.

## 9. Optional future verification script

An optional generic script may later be implemented at
`tools/windows/Verify-BmoBackup.ps1`. It may accept explicit artifact,
checksum, and manifest paths; reject wildcards and extras; calculate SHA-256;
validate the sanitized manifest; write a sanitized result; and return nonzero
on failure.

It must never accept a passphrase, decrypt automatically, contain credentials,

implement or require the script; direct commands above are the canonical first
manual rehearsal.
