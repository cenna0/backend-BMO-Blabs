# P9.1 Off-VPS Backup Options

**Decision status:** `OPERATOR_APPROVAL_REQUIRED`  
**Current state:** no destination, account, upload, or external credential has
been selected. Local encrypted backup and isolated restore are verified; full
disaster recovery is incomplete until an off-VPS copy is approved and restored.

The comparison uses current official documentation checked on 2026-08-04.
All options receive the already-encrypted `.dump.gpg` artifact; provider-side
encryption is not treated as a replacement for client-side encryption.

## Options

| Option | Free/cost model | API/auth | Versioning/retention | Restore and risks |
|---|---|---|---|---|
| Operator-owned second host/NAS over Tailscale | `$0` incremental storage if an existing host and disk are available; hardware, power, and Tailscale account ownership are operator costs | SFTP/SSH or rclone; Tailscale identity/ACLs; private route, no public bucket | Filesystem snapshots or a retention script; versioning is not automatic | Simple `rclone copy`/SFTP restore and no vendor lock-in; second host can be offline, lost, or ransomware-exposed unless append-only/snapshots are used |
| Backblaze B2 | First 10 GB free; then `$0.00695/GB-month`; free upload and Class A/B transactions in the current transaction page; egress free up to 3× average monthly storage, then `$0.01/GB` | S3-compatible API or native API; bucket-scoped application key; least-privilege key | Lifecycle rules hide/delete old versions; Object Lock is available and has no extra feature charge, but locked data cannot be deleted early | Strong backup fit and low cost; account/key lockout and vendor dependency; Object Lock/lifecycle configuration must be tested |
| Cloudflare R2 Standard | 10 GB-month free, 1M Class A and 10M Class B free; `$0.015/GB-month` after free tier; Internet egress free | S3-compatible API; scoped access key; Cloudflare account/R2 subscription required | Lifecycle rules support expiry/transition; provider versioning/immutability policy must be configured and verified | Easy S3/rclone integration and no egress fee; account/billing dependency and lifecycle misconfiguration risk |
| Google Drive through rclone | Personal account includes 15 GB shared across Drive/Gmail/Photos at no charge; 20 GB requires an account-specific paid Google One plan | OAuth via rclone Drive backend; client-side `rclone crypt` | Drive history/trash behavior is not a backup retention policy; enforce retention in the encrypted remote or use a dedicated folder/account | Familiar restore and rclone support; shared quota/account recovery risk and weaker backup-specific immutability |

## Preferred and fallback

**Preferred recommendation: existing operator-owned second host/NAS over
Tailscale**, if the operator confirms independent power, disk health, access
control, filesystem snapshot/append-only capability, and an owner other than
the VPS. It minimizes recurring cost and vendor lock-in. Upload only the GPG
artifact and checksum; use a dedicated restricted account and a separate
backup key. Tailscale's current Personal plan is free for up to six users, but
that does not create or pay for the second host.

**Fallback recommendation: Backblaze B2** with a private bucket, a prefix-scoped
application key, client-side GPG, checksum sidecars, lifecycle rules, and
Object Lock only after the retention/restore interaction is rehearsed. B2 is
preferred over R2 for the fallback because the current documented first-10-GB
free allowance, low storage rate, lifecycle rules, and Object Lock fit the
seven-daily/four-weekly policy.

Cloudflare R2 is a viable second cloud alternative when free egress and S3
compatibility are more important than the slightly higher storage rate.
Google Drive is a convenience fallback only, not the preferred recovery
boundary.

## Required operator actions

The operator must select the destination, create or designate the account,
define who owns its credentials, approve remote retention/immutability, and
authorize a test upload and restore. This branch creates no account and uploads
no data. A production sign-off must retain the selected destination, endpoint,
bucket/path, key owner, last successful remote checksum, and last restore test
date without recording credentials.
