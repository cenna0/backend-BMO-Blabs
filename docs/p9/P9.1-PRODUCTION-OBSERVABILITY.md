# P9.1 Production Observability Plan

Status: proposed; private operator signals only. No new monitoring service is
added by P9.1.

## Database signals

Collect privately: liveness/readiness result, PostgreSQL version, migration
state and duration, active/idle connection count, pool saturation, transaction
errors, query latency, lock waits, deadlocks, database size, data-directory
disk use, restart count, OOMKilled, and cgroup memory/CPU/PID usage. Health
responses must not expose DSNs, hostnames, schema SQL, table contents, or
credential errors.

## Backend signals

Record request count/status/latency, event-loop delay, Prisma pool saturation,
database error class, login failures, refresh replay detections, invitation
creation/use, pairing issue/claim/failure, rate-limit events, and audit-write
failures. Use event type and outcome labels, not user IDs, email addresses, raw
device IDs, tokens, codes, or high-cardinality metadata.

## Backup signals

Record the timestamp and result of the latest local dump, encryption/checksum
verification, upload, retention pass, artifact size, available staging disk,
remote object existence, and latest restore rehearsal. Alert on stale age,
checksum mismatch, wrong-key failure, missing remote artifact, or retention
failure.

## Security signals

Monitor repeated failed logins, refresh replays, pairing abuse, operator-route
access attempts, malformed/expired token spikes, and unexpected secret-file
permission changes. Log only sanitized correlation IDs, actor identity where
safe, event type, target identity where safe, outcome, and bounded metadata.

## Thresholds and ownership

The proposed thresholds are in `P9.1-PRODUCTION-RESOURCE-BUDGET.md` and the
backup thresholds in `P9.1-BACKUP-MONITORING-AND-RESTORE.md`. A private
operator dashboard or existing Beszel/journald/Docker inspection may consume
these signals. An external alert destination is
`OPERATOR_APPROVAL_REQUIRED`; WhatsApp and email alerting are out of scope.

## Recovery evidence

Every canary observation window must retain a timestamped summary of Git/image
identity, health, resource counters, migration state, backup state, and
rollback decision. Evidence must contain no secrets, raw tokens, invitation
values, pairing codes, DSNs, or database rows.
