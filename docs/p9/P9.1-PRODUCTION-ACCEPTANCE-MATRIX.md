# P9.1 Future Production Acceptance Matrix

This is a future canary gate, not evidence that production has been migrated.
Each row requires the exact command/test output to be attached at the stated
evidence path. Any stop condition invokes the rollback runbook.

| Area | Acceptance item | Test/evidence | Expected result | Stop / rollback |
|---|---|---|---|---|
| Git/image | final main SHA and source label | `git rev-parse HEAD`; image inspect | approved SHA, no feature image reuse | mismatch: stop |
| Git/image | dependencies and secrets | lockfile, audit, layer/secret scans | pinned, zero secret artifacts | finding: stop |
| Contract | Hardware Contract | SHA-256 of locked file | `633e398a7fa39a3ebc469af7f9ca46fd04890339bb132ec7de2c2286207c6a44` | mismatch: rollback |
| PostgreSQL | private topology | `docker inspect`, listener/network checks | pinned digest, no public 5432, healthcheck | exposure: stop |
| PostgreSQL | zero migration | `prisma migrate deploy` + `_prisma_migrations` query | both P9.1 migrations applied once | failure: preserve DB |
| PostgreSQL | idempotence | repeat `migrate deploy` | no new migration/error | drift: stop |
| PostgreSQL | persistence | restart candidate DB and query fixture | rows/settings/audit remain | mismatch: rollback |
| PostgreSQL | connection/resource gates | bounded pool/exhaustion test, cgroup stats | below approved saturation/memory thresholds | breach: stop |
| Backup | local artifact | dump/checksum/GPG/manifest/retention verification | seven daily/four weekly encrypted copies; no persistent plaintext | failure: stop |
| Backup | manual off-VPS pull | operator pull of artifact, checksum, and sanitized manifest | personal-computer copy; no remote account/provider required | missing or incomplete pull: no-go |
| Backup | PC retention | inspect four latest weekly plus three protected milestones | milestone copies are outside ordinary rotation | deletion risk: stop |
| Restore | exact PC copy | checksum/decryption + restore into fresh target + application queries | schema, migrations, counts, ownership, login, `/api/v1/me` valid | mismatch: quarantine |
| Recovery | RPO acknowledgment | record transfer cadence and last verified PC copy | approximately seven-day worst-case RPO accepted for initial scale | unacknowledged RPO: no-go |
| Auth | invite lifecycle | valid/expired/revoked/used/concurrent registration | one-use atomic, generic errors | race/enumeration: rollback |
| Auth | login/password | success, wrong password, disabled account, rate limit | Argon2id, generic response, sanitized audit | leak: stop |
| Auth | access token | malformed/expired/wrong algorithm/revoked session | reject safely; minimal claims | acceptance failure: rollback |
| Auth | refresh lifecycle | rotate, concurrent refresh, replay, logout current/all | one successor; family replay revocation | double success: stop |
| Device | ownership | cross-user list/get/update/unpair/IDOR cases | consistent denial; no enumeration | exposure: rollback |
| Device | pairing | issue/claim/expiry/revoke/replay/race | six digits, one claim, bounded/rate-limited | hardware binding missing: feature off |
| Settings | invariants | timezone/voice/range/default-device concurrency tests | Asia/Jakarta and Prudence rules enforced | violation: rollback |
| Proxy | client identity | spoofed XFF/X-Real-IP/Forwarded tests, IPv4/IPv6 | proxy-only identity; no bypass | bypass: stop |
| Ops | private DB routes | unauthenticated/direct/authorized probes | disabled or strongly protected, sanitized | leak/mutation: rollback |
| Regression | public routes | `/health`, `/livez`, `/readyz` | 200/404/404 unchanged | change: rollback |
| Regression | legacy voice/WebSocket | existing Backend/Audio/Hermes tests | unchanged contract, Piper primary, Kokoro fallback | regression: rollback |
| Regression | RVC disabled | health payload and logs | disabled/absent is not degraded | degraded-only defect: stop |
| Operations | monitoring/rollback | alerts, restart, OOM, disk, backup checks | signals private and actionable | missing signal: no-go |

Evidence should be stored under the approved P9 evidence location with redacted
logs and no credentials, raw tokens, invitation secrets, pairing codes, backup
keys, database contents, or generated data files.
