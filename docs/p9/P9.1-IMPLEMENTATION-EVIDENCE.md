## Private topology

`p9.1-compose.yml` defines a dedicated project `bmo-p9-1` with PostgreSQL and
candidate backend on an internal-only Docker network. No candidate port is
published. PostgreSQL is limited to 768 MiB, 1 CPU, and 20 configured
connections; the candidate backend is limited to 512 MiB and 1 CPU. Persistent
database data, password, JWT/pepper values, and backup passphrase are external
to Git. The backend entrypoint reads the file-backed database secret as a
short-lived privileged step, then runs the application as UID/GID 1000 with no
effective capabilities.

The candidate Dockerfile contains the Prisma migration inputs, but migrations
are invoked explicitly with `prisma migrate deploy`; no container-startup
migration is configured.

## Backup and restore

The operator scripts use `pg_dump --format=custom --no-owner --no-privileges`
inside the private PostgreSQL container. The stream is encrypted locally with
GnuPG symmetric AES-256 using an external passphrase file, written atomically,
and accompanied by a SHA-256 checksum. Retention keeps seven daily and four
weekly encrypted artifacts. Restore validates the checksum, refuses the
primary database name, creates a fresh target, decrypts in a pipe, and runs
`pg_restore` with the configured PostgreSQL user.

Validation results:

- Encrypted backup checksum: `cee0412189a231e565840f359ca36093aaf3305017345aa3ea53d78c3d3010c2`.
- GPG verification: AES-256, salted/iterated, SHA-512; custom dump listed 90
  restore entries.
- Retention: 7 daily and 4 weekly artifacts after over-retention runs.
- Restore target: isolated `bmo_restore_20260804b`.
- Restored rows: 3 users, 3 password credentials, 6 invitations, 5 sessions,
  1 device, 2 pairings, 3 user settings, 1 device setting, and 31 audit events.
- Restored password prefixes: 3 rows with `$argon2id$`.
- Restored ownership check: 0 orphan devices.
- Restored timezone values: `Asia/Jakarta` only.
- Application-level login and `/api/v1/me` query against the restored target:
  passed.

The off-VPS backup destination and provider remain OPEN. Disaster recovery is
