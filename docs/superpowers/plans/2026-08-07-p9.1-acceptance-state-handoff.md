# P9.1 Acceptance State Handoff and CLI Entrypoints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the P9.1 acceptance tooling so pre-fixture evidence is manifest-free, stateful workers use an explicit host-to-runtime handoff, and every documented npm command executes its CLI exactly once.

**Architecture:** Keep a host canonical fixture manifest at the operator-owned path with mode `0600`; use a separate container-local tmpfs state file owned by `1000:1000`; copy only through a fixed read-only source mount and structured worker output, never through environment values or command arguments. Pre-fixture evidence will not create, mount, or validate state. A dedicated CLI entrypoint will call exported command logic directly, leaving implementation modules side-effect free.

**Tech Stack:** Node 22, TypeScript, Vitest, Docker CLI, Prisma 7, existing P9 operator modules.
