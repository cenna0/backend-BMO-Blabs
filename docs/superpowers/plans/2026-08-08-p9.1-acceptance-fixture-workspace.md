### Task 2: Implement the minimal protected workspace helper

**Files:**
- Create: `backend/src/p9/operator/acceptance-workspace.ts`
- Modify: `backend/src/p9/operator/acceptance-fixture.ts`

- [ ] **Step 1: Define exact workspace metadata and filesystem interfaces.**

  Export the `0700` workspace contract, direct-child state filename, and an adapter with `lstatSync`, `mkdirSync`, and directory-entry operations. Default expected owner/group to the current host process UID/GID and allow injected IDs for deterministic tests.

- [ ] **Step 2: Implement absent creation and EEXIST revalidation.**

  Validate an absolute state path whose basename is `fixture-state.json`. `lstat` the parent; on `ENOENT`, call non-recursive `mkdirSync(parent, { mode: 0o700 })`, then always `lstat` the final path. On `EEXIST`, skip mutation and perform the same final validation. Reject symlinks, non-directories, wrong owner/group, special bits, or any mode other than `0700` without chmod/chown.

- [ ] **Step 3: Validate permitted children without deletion.**

  Read only direct entries under the validated workspace. Permit no name other than `fixture-state.json`; reject `.tmp` and every unexpected entry. For the manifest, require a regular non-symlink file owned by the host operator with exact `0600`. Do not recursively traverse or delete content.

- [ ] **Step 4: Strengthen state schema exactness.**

  Make `validateFixtureState` reject non-object values, wrong field types, extra keys, malformed run/database identities, and credential-bearing fields while retaining the existing exact synthetic identity checks. Keep the existing atomic `O_EXCL|O_NOFOLLOW` temporary write and rename behavior.

  Run the Task 1 command. Expected: all workspace, state, fixture, and clean-host tests pass with zero failures.
