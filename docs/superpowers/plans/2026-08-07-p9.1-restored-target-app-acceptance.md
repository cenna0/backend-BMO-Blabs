# P9.1 Restored-Target Application Acceptance Tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with verification checkpoints.

**Goal:** Add repository-supported, non-executing tooling for isolated application acceptance against an existing `bmo_restore_*` database.

**Architecture:** Pure validators protect restore-target, network, identity, migration, and secret-file boundaries before Docker or database effects. Disposable Docker commands reuse the candidate backend image on the existing private PostgreSQL network without starting PostgreSQL. A synthetic fixture worker uses the real Argon2id helper, records exact state, and cleans only verified fixture-owned rows; a sanitized HTTP runner and aggregate evidence worker prepare the future one-login acceptance.

**Tech Stack:** Node 22, TypeScript, Vitest, Prisma 7, Argon2id, Express, Docker CLI, existing P9 candidate image/network.
