# P9.1 Production Secret Operations Implementation Plan

> **For agentic workers:** Execute this plan inline in the isolated readiness worktree; it is documentation-only and must not provision secrets, change runtime configuration, merge, or deploy.

**Goal:** Lock and explain P9.1 production secret ownership, file-based injection, service isolation, recovery, rotation, and incident handling for first-canary operator review.

**Architecture:** The BMO operator owns all P9.1 production secrets. Root-controlled files under `/opt/bmo/secrets/p9.1/` are mounted read-only at `/run/secrets/<secret-name>` only into the consuming service. The first-canary backup model remains symmetric GPG AES-256; the recommended asymmetric model is documented as a future improvement.

**Tech Stack:** Markdown documentation, Docker read-only secret mounts, PostgreSQL roles, HS256 JWT, HMAC-SHA-256 pairing codes, GPG AES-256 backup encryption, existing verifier and shell-based evidence checks.
